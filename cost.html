CASE STUDY 02

AWS 비용을
월 약 66% 줄인 과정

Cost Explorer와 하이퍼빌링으로 비용을 분석하고, 실행 환경·리소스 규모·약정을 함께 개선했습니다.

개선 범위와 목표

씨피랩스에서 2~3인 팀으로 AWS·Azure·GCP·NHN Cloud에 걸친 300대 이상의 인프라를 운영했습니다. 그중 AWS 환경은 2024년부터 2026년까지 사용 리소스와 실행 환경, 약정 방식을 함께 조정하며 비용을 줄였습니다.

사용하지 않는 자원을 정리하는 데서 그치지 않고, 서비스에 필요한 규모와 실행 방식을 다시 살폈습니다. EC2 기반 서비스는 Fargate로, 정적 사이트는 S3로 이전하고 RDS 인스턴스와 컴퓨팅 약정도 개선했습니다.

비교 대상은 대파 단일 서비스가 아닌 회사 전체 AWS 월 비용입니다.

비용 분석과 개선 대상 선정

AWS Cost Explorer와 메가존클라우드의 하이퍼빌링을 이용해 AWS 사용 현황과 비용 내역을 확인했습니다. 사용 중인 리소스와 서비스 구성을 함께 검토하며 규모를 줄이거나 실행 환경을 바꿀 대상을 정했습니다.

리소스 사용불필요한 리소스 정리와 인프라 규모 축소

Fargate 이전과 RDS Graviton 전환

EC2 기반 서비스를 ECS Fargate로 이전

Metadium Explorer API와 Sync, WEB2X 서비스, KISA 확산 과제인 E-mobility 등의 워크로드를 EC2에서 ECS Fargate로 이전했습니다. 실행 환경 변경과 함께 인프라 규모를 조정하며 비용을 줄였습니다.

MySQL·PostgreSQL RDS를 Graviton으로 전환

주로 사용하던 MySQL RDS와 Metadium Explorer의 PostgreSQL을 포함해 모든 RDS를 Graviton 기반 인스턴스로 전환했습니다. 애플리케이션 실행 환경뿐 아니라 데이터베이스 인스턴스 구성도 함께 개선했습니다.

정적 사이트의 S3 이전

정적 콘텐츠를 제공하기 위해 운영하던 EC2 환경을 S3 기반으로 변경했습니다. 서비스 종료 안내용 임시 페이지, 회사 브랜드 사이트, Metadium 소개 사이트, WEB2X 소개 사이트 등이 대상이었습니다.

콘텐츠는 S3에 저장하고 CloudFront와 ACM을 함께 구성했습니다. 정적 페이지를 위해 별도 서버를 유지하는 구성을 줄이면서 HTTPS로 콘텐츠를 제공하도록 했습니다.

RI 중심에서 Savings Plans 중심으로

기존 EC2 RI 중심의 약정 운영 방식을 Savings Plans 중심으로 바꿨습니다. Fargate 이전 이후의 사용량까지 반영할 수 있도록 EC2와 Fargate의 예상 사용금액을 함께 계산해 약정 규모를 정했습니다.

예상 사용금액의 약 80%를 Savings Plans로 약정하고, 나머지 약 20%는 온디맨드로 운영하는 기준을 적용했습니다. 전체 사용금액을 모두 약정하지 않고 변동분을 남기는 방식이었습니다.

2024~2026년 개선 결과

개선 전

2024~2026년 개선 전후의 월 비용 비교이며 금액은 근삿값입니다. 약 66%는 두 총액을 기준으로 계산했습니다.

월 AWS 비용은 약 6만 5천 달러에서 약 2만 2천 달러로 줄어, 월 약 4만 3천 달러를 절감했습니다.

이 결과에는 서비스 종료로 줄어든 비용도 포함됩니다. 다만 전체 감소분에서는 리소스 규모 축소의 영향이 더 컸습니다. 서비스 이전과 인스턴스 구성 변경, 약정 관리를 함께 진행한 결과입니다.
